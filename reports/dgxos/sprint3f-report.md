## A. Vision: CPU vs GPU

Gemma 3 4B Q4_K_M, Ollama 0.40.8; тот же экран Sprint 3B, temperature 0, seed 42, context 4096. Подтверждение: **35/35 слоёв на GPU**, `CLIP using CUDA0 backend`, `/api/ps` с ненулевым size_vram. GPU-запросы потоковые для измерения TTFT, CPU baseline взят из сохранённых данных 3B.

| Задание | CPU latency | GPU latency | CPU → GPU TTFT | CPU → GPU generation tok/s |
|---|---:|---:|---:|---:|
| Фигуры/цвета, первый запрос после загрузки | 265,737 с | 11,073 с | не измерялся → 10,18 с | 0,327 → 74,43 |

| Новый содержательный UI-тест | новый тест | 1,876 с | — → 0,57 с | — → 75,93 |

Первый GPU vision-запрос включает загрузку 3,39 с и prompt processing 6,76 с. Последующие запросы прогреты; кэш изображения/контекста влияет на сравнение. CPU baseline получен во время отказа GPU, а история прогрева между сериями не полностью совпадает: это практическое сравнение, не чистый контролируемый speedup benchmark. Generation tok/s не включает обработку изображения и загрузку.

**Независимая оценка ответов:**

- OCR: INV-0042, USD 128.50, PAUSED — **3/3**. Ответ обёрнут в Markdown code fence.
- Фигуры: три синих круга и квадрат распознаны; оранжевый квадрат снова назван жёлтым, как на CPU.
- Отдельный запрос действия: START, зелёная, слева — правильно. В комбинированном запросе опять перечислены обе кнопки вместо единственного выбора.
- Новый экран: задача PAUSED, approval PENDING, processed 8/10, RESUME disabled, REVIEW запрашивает согласование, CANCEL отбрасывает работу. Эталон: REVIEW, объяснение ожидания approval, **2** оставшихся элемента. Модель правильно выбрала REVIEW и объяснила ограничение, но ответила **8** вместо 2 — **2/3 полей**.

Эталон зафиксирован отдельно в `sprint3f-ui-expected.json`. Это тест интерпретации изображения и текстового ответа; реальные действия не выполнялись, безопасность агента не сертифицировалась.

## B. Audio: Whisper base на CUDA

Существующий whisper.cpp 1.9.5-dev, commit `231638a0717b7822784297e5980965ffcec05810`; прежняя запись 7,849 с/24 слова, base multilingual, язык en, 4 CPU threads, прежние CLI-параметры. Логи подтверждают **CUDA0 backend**, модель 147,37 MB на CUDA0 и GPU execution buffers; CPU fallback отсутствует.

| Запуск | CPU wall | GPU wall | GPU загрузка модели | Сумма ASR-стадий² | WER |
|---|---:|---:|---:|---:|---:|
| 1 | 1,852 с | 1,437 с | 168,31 ms | 237,18 ms | 0% |
| 2 | 1,266 с | 0,716 с | 53,33 ms | 187,09 ms | 0% |
| 3 | 1,285 с | 0,729 с | 57,61 ms | 184,23 ms | 0% |

² Внутренние таймеры whisper.cpp: mel + sample + encode + decode + batchd + prompt, отдельно от load. Внутренний total: 421,01 / 253,51 / 254,03 ms; внешнее wall включает также запуск процесса, CUDA/backend initialization и завершение. Разницу между wall и load нельзя целиком называть обработкой аудио. Каждый запрос — новый CLI-процесс; второй/третий используют прогретые файловые/JIT-кэши, не постоянно загруженную модель.

GPU оказался быстрее соответствующих CPU запусков, особенно двух последующих (~1,76× по wall). Но первый GPU запуск **1,437 с медленнее самого быстрого CPU 1,266 с**: на короткой записи overhead важен. Для всех трёх WER=0 после нормализации регистра/пунктуации. Пик общей занятой RAM 4,08–4,23 GiB, наблюдаемый GPU utilization до 25%, power до 14,18 W. Синтетическая чистая запись не представляет шумную речь/акценты.
